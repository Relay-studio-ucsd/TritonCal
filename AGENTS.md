# AGENTS.md

Instructions for every AI coding agent working in this repository, whatever the tool.

1. **This is the only source of agent instructions.** Agent instructions belong in this file; project knowledge belongs in MAINDOC.md. Never put a copy or variant of these instructions anywhere else.
   - **Entry files may only point here.** Some tools automatically load only a file with their own name, so these entry files are allowed, at these exact paths only: `CLAUDE.md`, `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`. The whole file must be one line: `@AGENTS.md` (an import, for tools that support it, such as Claude Code), or `Read AGENTS.md first.` for tools that don't. Never add rules, notes or anything else to them, and never create them elsewhere (for example in a subfolder). `tests/agent-entry.test.cjs` enforces this.
   - **Tool-specific instruction folders and personal files are git-ignored:** `.claude/`, `CLAUDE.local.md`, `.cursor/`, `.gemini/`, `.github/instructions/`. Never force-add them (`git add -f`), and never remove those `.gitignore` entries. When a tool introduces another such folder or file, add it to `.gitignore`, or to the list above if it can be a one-line pointer, in the same change.
2. **Read [MAINDOC.md](MAINDOC.md) first.** §1 holds the project's hard rules (passive capture only, privacy, zero dependencies), which are non-negotiable, and the working conventions. §5 explains the extension architecture.
3. **One documentation file.** All technical documentation lives in MAINDOC.md. Do not create other technical Markdown files. The only other Markdown files are this file, the READMEs and `extension/PRIVACY.md`. The READMEs and PRIVACY.md stay separate from MAINDOC.md, but they can and should be updated when the facts they state change. Put open questions in [GitHub Issues](https://github.com/Relay-studio-ucsd/TritonCal/issues), not in the docs.
4. **Attribute accurately.** Credit each decision or piece of work to the person who made it, using the git name recorded in the commit history (`git log`, PR authors), not whoever is currently giving instructions. Never invent or generalize authorship. Text written by an AI assistant is credited to that model by name, matching the `Co-Authored-By` trailer of the commit that adds it.
5. **Language.** Write MAINDOC.md and this file in English. READMEs are English first (`README.md`), with the Chinese version in `README.zh-CN.md`.
6. **Move code, don't retype it.** Use `git mv` for moves and targeted edits for changes, and check the result against the previous version with `git diff`. Run `npm test` before reporting work as done.
